**담당: 13~14쪽 전처리 → 30쪽 시스템 구성 → 31쪽 영상 시연 → 마무리.**

- 기준: [시스템 구성 추가 PPT · 31쪽](강판_결함_분석_발표자료_시스템구성추가.pptx).
- 13~14쪽은 합쳐서 **55초**, 구성도는 **40초**, 영상은 **3분**, 마무리는 **20초**입니다. 담당 구간 합계는 약 **4분 55초**이며, 중간에 다른 팀원 발표가 있습니다.
- 아래 전체 시각은 팀 발표 **20분 20초 구성** 기준입니다. 영상은 **17:00에 시작**합니다.
- 진행 메모는 읽지 않습니다. 영상 중에는 문장을 말한 뒤 쉬어도 됩니다. 남는 시간은 화면을 보여주는 시간입니다.
- 영상의 배경음악은 발표 음성과 별도입니다. 영상에서 기술 설명을 다시 길게 하지 않습니다.

### 13쪽 · 김현모 — 누적 OpenCV 전처리의 변화

**전체 06:00–06:25 · 25초**

**발표자: 김현모**

> **진행 메모 · 읽지 않음:** 채영지 발표 이후 이어받습니다. 전처리 순서는 사진을 가리키며 설명합니다.

저는 같은 강판 이미지에 전처리를 순서대로 적용하면서, 화면의 변화와 모델 성능을 함께 확인했습니다. CLAHE로 대비를 높이고, Bilateral로 잡음을 줄인 뒤 Sharpen과 Opening을 적용했습니다. 이미지가 더 선명해 보일 수는 있지만, 그 변화가 실제 결함 판별에도 도움이 되는지는 별도로 검증했습니다.

### 14쪽 · 김현모 — 누적 전처리 후 패치 F1 하락

**전체 06:25–06:55 · 30초**

**발표자: 김현모**

> **진행 메모 · 읽지 않음:** 모델은 Extra Trees, 검증 패치는 216개입니다. 원본과 최종 F1 두 수치에 집중합니다.

성능은 Extra Trees로 검증 패치 216개를 평가했습니다. 원본 입력의 F1은 62.33퍼센트였고, 전처리를 모두 적용한 뒤에는 59.65퍼센트로 낮아졌습니다. CLAHE 이후 필터를 더한 조건들도 CLAHE 기준보다 F1이 낮았습니다. 따라서 이 누적 전처리 조합은 최종안으로 채택하지 않았습니다. 필터를 많이 적용하는 것보다 실제 판별 성능을 기준으로 필요한 처리를 선택해야 한다는 점을 확인했습니다.

### 30쪽 · 시연 전, 검수 시스템 한눈에 보기

**전체 16:20–17:00 · 40초**

**발표자: 김현모**

> **진행 메모 · 읽지 않음:** 구성도에서 사용자 화면 → Python API → 두 모델 → 결과 저장 순서로 짚습니다. 설명을 마친 뒤 31쪽으로 넘깁니다.

이제 분석한 모델을 실제로 사용할 수 있도록 구현한 웹을 설명드리겠습니다. 사용자가 사진과 검사 메뉴를 선택하면 Python API가 해당 모델을 호출합니다. 품질 검수는 기본 ResNet18 TTA로 정상과 불량 의심을 판단하고, RF 등 다른 모델도 선택할 수 있습니다. 결함 위치는 별도의 U-Net으로 분석해 마스크와 후보 박스를 보여줍니다. 두 기능은 각각 실행하며, 결과는 PNG와 CSV로 저장할 수 있습니다. 영상에서는 판정, 위치 확인, 파일 저장 순서로 보시겠습니다.

## 리허설 메모 · 읽지 않음

- 14쪽 평가 모델은 **Extra Trees**입니다. 최종 웹의 기본 품질 검수 모델 **ResNet18 TTA**, 위치 모델 **U-Net**과 구분합니다.
- 30쪽은 사용자 화면 → Python API → 품질/위치 모델 → 결과 저장만 짚습니다. 분류 뒤 위치 분석이 자동 실행된다고 설명하지 않습니다.
- 영상의 정상 판정은 01:19쯤, 불량 판정은 01:44쯤, 위치 결과는 02:07쯤에 맞춰 말합니다.
- 불량 점수는 보정된 확률이 아닙니다. “불량 확률 몇 퍼센트” 대신 “판정 점수”라고 말합니다.
- 02:44 이후는 반응형 웹 화면이며, 아이폰 카메라 실시간 탐지나 Expo 앱 시연은 아닙니다.
- 전체 20분에 맞춰 앞 구간을 20초 줄였다면 영상 시작은 16:40, 영상 종료는 19:40, 마무리는 20:00입니다.
