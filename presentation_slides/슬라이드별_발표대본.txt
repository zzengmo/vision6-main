SteelVision ML 웹 구현 발표 대본
총 6장 · 약 2분 30초 · 영상 시연 후 발표

1장 · 약 20초
앞서 보신 웹은 React와 TypeScript로 화면을 구성하고, Python 서버를 통해 실제 모델을 호출하는 방식으로 구현했습니다. Figma 시안을 바탕으로 영상 메인과 기능 화면의 색상, 메뉴 구성을 통일했습니다. 화면과 모델 실행의 역할을 나누면서 사용자는 하나의 검수 흐름으로 이용할 수 있도록 구성했습니다.

2장 · 약 30초
첫 번째 어려움은 모델별로 입력 처리와 출력 형식이 다르다는 점이었습니다. 그래서 웹과 모델 사이에 어댑터를 두었습니다. 어댑터는 기존 추론 함수를 호출하고, 판정과 점수, 처리 시간, 이미지와 좌표를 화면에서 사용할 형식으로 정리합니다. 이때 원래 전처리와 판정 기준을 유지해 웹 연결 때문에 모델의 동작이 바뀌지 않도록 했습니다.

3장 · 약 30초
두 번째는 검사 상태 관리였습니다. 정상 이미지를 검사한 뒤 다른 이미지를 올렸는데 이전 결과가 남아 있으면 잘못 해석할 수 있습니다. 이미지나 모델, 판정 기준이 바뀌면 기존 결과를 초기화하도록 했습니다. AbortController로 브라우저 요청을 취소하고 요청 번호를 확인해서, 늦게 도착한 이전 응답이 새 화면에 표시되지 않도록 했습니다. 반대로 다운로드할 때는 결과를 유지하고 재추론이 발생하지 않도록 했습니다.

4장 · 약 25초
세 번째는 결과의 의미를 정확히 전달하는 문제였습니다. 분류 모델은 이미지 전체의 정상과 불량을 판단하고, U-Net은 결함과 배경을 픽셀 단위로 나눕니다. 그래서 두 결과를 별도 화면으로 구분했습니다. 분류 결과에는 임의의 박스를 붙이지 않았고, 위치 분석에서는 실제 예측 마스크와 원본 기준 좌표를 보여주었습니다. CSV 좌표도 같은 기준으로 저장합니다.

5장 · 약 20초
전처리 체험도 실제 추론과 분리했습니다. 사용자는 CLAHE나 Bilateral 같은 옵션을 바꾸면서 원본과 처리 결과, 히스토그램을 비교할 수 있습니다. 하지만 이 설정이 모델 입력까지 바꾸면 학습 당시 조건과 달라질 수 있습니다. 따라서 체험은 별도의 처리 경로로 실행하고, 실제 검수에서는 모델의 원래 전처리를 유지했습니다.

6장 · 약 25초
화면은 CSS Grid와 미디어 쿼리로 반응형으로 구성했습니다. PC에서는 설정과 결과를 좌우로, 모바일에서는 세로로 배치하고 전체 메뉴를 제공했습니다. 구현 후에는 실제 정상과 불량 검사, 위치 분석, 다운로드까지 브라우저에서 확인했습니다. PNG와 CSV도 다시 읽고 좌표 범위를 검사해서 화면 표시부터 모델 실행, 결과 저장까지 전체 흐름을 검증했습니다.
